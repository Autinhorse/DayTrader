# 0016 开盘区间交易的快速模拟

日期：2026-10-17　状态：已采纳　依据：用户同意"回测开盘区间边缘反向 / 假突破收回，以及只在波动大的日子做的过滤效果"，
要求按今年各季度分开统计

## 背景

决策 0015 的分析只看走势分类（收盘是否在区间外），没有止损、目标、成本，不能回答"这样做能不能赚钱"。

## 选项

- A. 写成 `user/strategies` 里的策略，用正式回测引擎跑：结果最可信，但引擎逐个 1 秒 bar 驱动，
  10 只证券 × 2.8 年要跑很久；而且要比较几十组规则和参数，每组都要跑一遍。
- B. 在 analytics 里用清洗后的 1 分钟 bar 写一个快速模拟器：几秒跑完一组，方便按季度、按特征分档、扫参数；
  精度不如正式回测，所以成交假设一律取保守的一边。

## 结论

采用 B 做筛选，新模块 `trader.analytics.or_trades`（只依赖 analytics 和 data）：

1. `load_minutes`：与日内波动报表相同的清洗、复权，跳过提前收盘日和 ADR 不足的日子；notebook 缓存在 `reports/or_trades_cache/`。
2. `Rule`：三种规则 fade（边缘反向）、reclaim（假突破收回）、breakout（突破跟随，对照）；目标 mid / opposite / close；
   止损距离以 ADR 为单位。每只证券每天最多一笔，15:00 以后不开新仓，15:55 平仓。
3. 成交假设（保守）：同一根 bar 止损和目标都到了按止损；入场那根 bar 只查止损；限价单按限价（越过限价开盘的按开盘价），
   止损单、市价单另加 0.01 ADR 滑点；成本用报表的分档，买卖各扣一次。开盘区间只用第 n 分钟以前的 bar，信号只用走完的 bar。
4. 过滤条件的分档边界只用 2024–2025 的交易定（`fixed_bins`），再用到 2026，避免用评估段的分布挑日子。
5. 筛选出有希望的规则后，再写成正式策略用回测引擎确认；快速模拟的结果不直接作为上线依据。
